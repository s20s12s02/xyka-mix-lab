## Записи

### 2026-08-22 — Ложное срабатывание запрета «сыр»

- Контекст: контрактный тест запрещённых гастрономических профилей.
- Ошибка: тест искал `сыр` как произвольную подстроку.
- Последствие: допустимое слово «сырьё» в описании сигарного листа ошибочно блокировало четыре табака.
- Причина: проверка строк не учитывала границы слов.
- Исправление: запрет проверяется по нормализованным русским токенам.
- Защита от повторения: добавлен регрессионный пример, подтверждающий, что «сырьё» не равно вкусу «сыр».
- Проверка: `python3 -m unittest -v tests.test_data.InventoryContractTests.test_inventory_excludes_banned_profiles_and_documents_lavender`.

### 2026-08-22 — Зависшая загрузка шрифта с CDN

- Контекст: локальное встраивание открытого кириллического шрифта для автономного HTML.
- Ошибка: запрос к unpkg не получил ни одного байта за 30 секунд.
- Последствие: первая попытка не создала файлов.
- Причина: внешний CDN не отвечал из текущей сети.
- Исправление: переменный TTF и OFL-лицензия скачаны из официального репозитория Google Fonts с ограничением таймаута.
- Защита от повторения: для внешних загрузок задавать `--connect-timeout` и `--max-time`, после запроса проверять размер и SHA-256.
- Проверка: `shasum -a 256 src/assets/oswald-variable.ttf src/assets/licenses/OFL-Oswald.txt`.

### 2026-08-22 — Playwright не стартовал из глобального npm-кэша

- Контекст: запуск браузерной QA через штатную Playwright-обёртку.
- Ошибка: npm вернул `EPERM`, потому что в `~/.npm/_cacache` есть чужие root-owned файлы.
- Последствие: первый вызов `playwright-cli --help` завершился до запуска браузера.
- Причина: права глобального пользовательского npm-кэша, не связанные с проектом.
- Исправление: для QA назначен отдельный временный кэш `/private/tmp/xyka-npm-cache`; `sudo` и глобальные настройки не менялись.
- Защита от повторения: браузерные команды проекта запускать с отдельным `NPM_CONFIG_CACHE`.
- Проверка: Playwright CLI вывел справку и готов к запуску.

### 2026-08-22 — Декоративная дорожка переключателя перехватывала клик

- Контекст: мобильная проверка выключения Sebero Strawberry на «Моей полке».
- Ошибка: прозрачный нативный checkbox был меньше визуальной дорожки, а соседний `span` перехватывал pointer-событие.
- Последствие: Playwright не мог надёжно нажать checkbox; поведение зависело от синтетического клика по `label`.
- Причина: hit-area была назначена декоративному элементу, а не контролу формы.
- Исправление: checkbox растянут на всю область 52×32 и поднят по z-index, декоративному `span` задано `pointer-events: none`.
- Защита от повторения: интерактивная область принадлежит нативному input; визуальные слои не принимают события.
- Проверка: повторный Playwright `uncheck` по роли checkbox и контроль выдачи без выключенного ингредиента.

### 2026-08-22 — Перерисовка checkbox во время `change`

- Контекст: повторная браузерная проверка переключателя «Моя полка».
- Ошибка: обработчик сразу пересоздавал весь список полки, включая только что нажатый checkbox.
- Последствие: состояние сохранялось правильно, но активный нативный контрол исчезал до пост-проверки браузера и терял фокус.
- Причина: слишком крупная область повторного рендера после локального изменения.
- Исправление: checkbox остаётся в DOM; отдельно обновляются счётчик, крепости, рекомендации и сохранённые списки.
- Защита от повторения: локальные form-controls не заменять внутри их собственного `change`, если структура списка не меняется.
- Проверка: полка показывает 25 из 26, checkbox остаётся unchecked, во всех видимых рецептах нет выключенного ингредиента.

### 2026-08-22 — Неверное имя команды изменения viewport

- Контекст: desktop QA через Playwright CLI.
- Ошибка: использована команда `resize-window`, которой в CLI нет.
- Последствие: первый «desktop» screenshot остался мобильного размера.
- Причина: имя команды было перенесено из другого браузерного интерфейса.
- Исправление: по справке CLI применена команда `resize 1440 900`, размеры проверены через `innerWidth/innerHeight`.
- Защита от повторения: для этого проекта использовать только зафиксированные в `qa/README.md` команды и проверять viewport численно до вывода.
- Проверка: новый screenshot имеет 1440×900, `scrollWidth === clientWidth`.

### 2026-08-22 — Playwright CLI блокирует `file://`

- Контекст: проверка автономного запуска финального файла.
- Ошибка: штатный CLI отклоняет протокол `file:` ещё до передачи URL браузеру.
- Последствие: `file://` нельзя было подтвердить тем же сеансом, которым проверялась адаптивность.
- Причина: защитное ограничение CLI, а не приложения.
- Исправление: финальный файл отдельно открыт напрямую headless Chrome по `file://`; адаптивные viewport проверены в том же HTML через локальный HTTP без внешних ресурсов.
- Защита от повторения: разделять проверку протокола и проверку viewport, фиксируя обе в QA-протоколе.
- Проверка: Chrome записал `qa/file-scheme-390.png`; страница выполнила встроенный JavaScript и показала рассчитанное число рецептов.

### 2026-08-22 — QA-кадр сохранил прежнюю прокрутку

- Контекст: повторная съёмка после визуальных правок.
- Ошибка: reload восстановил прежнюю позицию прокрутки, поэтому первый mobile capture начинался с выдачи, а не с шапки.
- Последствие: кадр не доказывал первый viewport и был непригоден для finish review.
- Причина: перед screenshot не была явно нормализована позиция страницы.
- Исправление: выполнен `window.scrollTo(0, 0)`, затем повторно сняты mobile, desktop и dark captures.
- Защита от повторения: перед evidence-capture всегда проверять верх документа и фактические размеры viewport.
- Проверка: на новых `qa/mobile-390.png` и `qa/desktop-1440.png` видна верхняя плашка 18+ и начало приложения.

### 2026-08-23 — Истёкшая авторизация GitHub CLI

- Контекст: подготовка нового публичного репозитория и GitHub Pages.
- Ошибка: `gh auth status` сообщил, что сохранённый токен аккаунта `s20s12s02` недействителен.
- Последствие: создание репозитория было невозможно до повторной авторизации.
- Причина: истёкшая или отозванная GitHub-сессия в системном keyring.
- Исправление: выполнен официальный device-flow `gh auth login --web`; пользователь подтвердил одноразовый код на GitHub.
- Защита от повторения: перед внешними изменениями всегда запускать `gh auth status`, не просить и не выводить полный токен.
- Проверка: `gh auth status` показывает активный аккаунт `s20s12s02`, протокол HTTPS и scope `repo`.

### 2026-08-23 — Sandbox запретил создать `.git`

- Контекст: инициализация нового репозитория в существующем каталоге проекта.
- Ошибка: первый `git init -b main` завершился сообщением `.git: Operation not permitted`.
- Последствие: рабочие файлы не изменились, репозиторий не был создан с первой попытки.
- Причина: запись пользовательских файлов была разрешена, но создание внутренней Git-метаобласти требовало отдельного повышенного разрешения.
- Исправление: тот же точный `git init -b main` повторён после запроса разрешения на эту операцию.
- Защита от повторения: создание или изменение `.git` в каталоге вне исходного workspace выполнять только с явным scoped-разрешением.
- Проверка: Git сообщил `Initialized empty Git repository`, ветка называется `main`.

### 2026-08-23 — Зарезервированное имя переменной zsh в мониторинге Pages

- Контекст: ожидание финальной сборки GitHub Pages после отправки документации.
- Ошибка: локальная команда использовала имя `status`, которое в zsh является read-only.
- Последствие: первый цикл мониторинга остановился после успешного ответа GitHub API; сборка сайта продолжилась независимо.
- Причина: имя shell-переменной не было проверено на совместимость с zsh.
- Исправление: переменные переименованы в `page_status` и `page_commit`.
- Защита от повторения: в zsh не использовать общие специальные имена (`status`, `pipestatus`) для служебных переменных.
- Проверка: исправленный цикл получил для commit `699cb43657032ae983e43680e382334425d7f54d` статус `built` без ошибки shell.
