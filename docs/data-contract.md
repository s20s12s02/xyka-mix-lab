# Контракт данных

## `inventory.json`

Ровно 26 объектов. Обязательны идентификатор, бренд, линейка, вкус, профиль, роли и теги, скрытый `strengthIndex`, публичный `strengthLabel`, сила аромата, максимальная доля, жаростойкость, предупреждения, калибровочная заметка и ссылки на источники.

## `analogs.json`

Каждая замена связывает исходную вкусовую роль с одним или двумя имеющимися табаками. Хранятся шесть частных оценок, итоговое сходство, различия, допустимые роли и предел доли. Итог вычисляется по весам 35/20/15/15/10/5 и не может быть ниже 0,70.

## `recipes.json`

Каждый рецепт содержит 2–4 компонента. Доли кратны 5, дают 100%, а граммы рассчитаны на 10 г. Скрытый индекс микса пересчитывается как средневзвешенный по массе; интерфейс получает только словесную категорию. Для `adapted` обязательны исходная формула, таблица замен, коэффициенты и объяснение. Для всех типов обязательны динамика вкуса, укладка, нагрев, ограничения, аллергены, уверенность и источники.

## Пользовательские диапазоны крепости

- 2,0–3,4: «Лёгкая»
- 3,5–4,4: «Средне-лёгкая»
- 4,5–6,4: «Средняя»
- 6,5–8,4: «Крепкая»
- 8,5–10,0: «Очень крепкая»

Числа из этого раздела являются внутренним инженерным контрактом и не включаются в пользовательский интерфейс.
