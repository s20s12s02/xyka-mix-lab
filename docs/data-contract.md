# Контракт данных

## `inventory.json`

Ровно 26 объектов. Обязательны идентификатор, бренд, линейка, официальное название вкуса, короткое служебное имя, профиль, `hook`, роли и теги, `copy.titleTerm/titleTokens/sensoryRole`, скрытый `strengthIndex`, публичный `strengthLabel`, сила аромата, максимальная доля, жаростойкость, стабильный `visualColor`, `iconKey`, предупреждения, калибровочная заметка и ссылки на источники. Предупреждения и источники являются внутренними полями контроля качества и не выводятся в интерфейсе.

## `analogs.json`

Каждая замена связывает исходную вкусовую роль с одним или двумя имеющимися табаками. Хранятся шесть частных оценок, итоговое сходство, различия, допустимые роли и предел доли. Итог вычисляется по весам 35/20/15/15/10/5 и не может быть ниже 0,70.

## `recipes.json`

Каждый рецепт содержит 2–4 компонента по убыванию доли. Доли кратны 5, дают 100%, а граммы рассчитаны на 10 г. Компонент дублирует официальный `brand` и `name` инвентаря. Скрытый индекс микса пересчитывается как средневзвешенный по массе; интерфейс получает только словесную категорию. Для `adapted` обязательны исходная формула, таблица замен, коэффициенты и объяснение. Для всех типов обязательны уникальное говорящее `name`, внутреннее `copyRationale`, `qualityScore ≥ 0,65`, внутренняя `notePyramid.top/heart/base`, динамика вкуса, `packing.method`, `packing.layout`, нагрев, внутренние ограничения, аллергены и источники. Поля recipe hook и уверенности отсутствуют.

Один неупорядоченный набор `tobaccoId` допустим только в одном рецепте. Пересечение `sum(min(доляA, доляB)) / 100` меньше 0,95 во всём каталоге и меньше 0,85 внутри публичной ячейки. В одной непустой ячейке 1–8 рецептов, один табак встречается не более трёх раз, а одна пара табаков — не более одного раза. `packing.layout.sectors` даёт 100% и один сектор на компонент; UI получает отдельные внутреннюю точку процента и внешнюю точку иконки. `packing.layout.layers` содержит минимум два слоя, 100% по высоте и каждый компонент ровно один раз; инструкция объясняет физический порядок закладки и переворота. `compote` содержит одну короткую инструкцию.

## Направления и совместимость

- `directions` содержит только публичные значения: `dessert`, `fruit`, `berry`, `citrus`, `drink`, `unusual`.
- `generationDirections` сохраняет одну из восьми внутренних групп только как генерационный след; прежние ID и fingerprint не являются контрактом.
- Публичное направление каждого рецепта определяется максимальным процентно-взвешенным профилем его фактических компонентов; при равенстве действует стабильный приоритет `unusual → drink → berry → dessert → fruit → citrus`.
- Состояние хранится под `xyka-mix-lab:v2`. Из v1 переносится только `availableIds`; избранное, «Пробовал», направление, крепость и фильтры сбрасываются. Новый сеанс получает `direction: null` и `strength: "любая"`.

## Пользовательские диапазоны крепости

- 2,0–3,4: «Лёгкая»
- 3,5–4,4: «Средне-лёгкая»
- 4,5–6,4: «Средняя»
- 6,5–8,4: «Крепкая»
- 8,5–10,0: «Очень крепкая»

Числа из этого раздела являются внутренним инженерным контрактом и не включаются в пользовательский интерфейс.
